## Anti-Patterns Verdict

Pass on every absolute ban; one fresh first-order leak; one growing second-order pressure.

**LLM assessment.** Side-stripes >=2px, gradient text, glassmorphism, hero-metric template, modals-as-first-thought, color-as-only-severity, bounce/elastic easing, animated layout, pure black/white: all clean. The Three-Voice typography contract holds across all results surfaces except `GuidedExplanation`, which uses Tailwind's `font-mono` instead of the project's `.font-numeric` handle (no `tabular-nums`, no fallback stack). Two **em dashes** leak into rendered UI: `lib/warnings.ts:48` ("Piecewise — No Global Polynomial") and `ExamplesPanel.tsx:246` ("Deferred — Osculating (Bessel-style)"). The **12-card example grid** in a 4-up `xl:grid-cols-4` layout, with identical internal structure (title / subtitle / tinted Badge / source note / outline "Load Example" button), is approaching the identical-card-grids anti-pattern.

**Deterministic scan.** `node detect.mjs --json frontend/src` returned `[]`. No automated rules tripped against any markup file. The detector does not currently cover Tailwind class drift (`font-mono` vs `font-numeric`), em dashes inside string literals, raw enum-as-label patterns, or category-grid density. All five priority issues below are LLM-only catches that the deterministic scan cannot see, by design.

**Visual overlays.** Browser injection was not attempted on this run because the deterministic detector returned zero findings, so there is nothing for a `detect.js` overlay to mark. Live screenshots were captured at three states (`empty-bench`, `linear-overview`, `linear-polynomial`, `linear-evaluations`) and saved under `.impeccable/critique/screens/2026-05-26-*.png` for reference.

## Overall Impression

The Analysis Bench is holding together remarkably well after Phase 2 added eight methods, eleven warning codes, and twelve example cards. The Inset Containment Rule scaled cleanly: zero new side-stripes, zero gradients, zero modal-as-first-thought introductions. The strongest opportunity is small but visible everywhere a user lands after computing: raw API method codes leaking into user-facing column headers and alert bodies. One pull request on a shared `lib/method-labels.ts` plus a backend-code `METHOD_LABEL` map would lift heuristic 2 from 2 to 4 and recover roughly four points.

## What's Working

1. **Inset Containment Rule scaled.** Eight new warning codes, eight new methods, eleven new warning labels, all routed through `bg-warning/5 ring-1 ring-inset ring-warning/20` (or info/destructive equivalents). Zero side-stripes, zero gradients, zero modals introduced. The DESIGN.md "Don't" list was treated as a contract.
2. **Three-voice typography enforced via CSS handles.** `.font-numeric`, `.font-math`, `.font-label` are defended by a comment block in `index.css:178-209`. Newton tables, Neville tables, Barycentric weights, basis polynomials, and KaTeX displays all read as one numeric voice. The single deviation in `GuidedExplanation` is a four-line fix.
3. **Lazy-loading on the right surfaces.** `ResultsPanel.tsx:21-37` defers Recharts and KaTeX behind `Suspense + Skeleton`, addressing the prior audit's P2 perf finding directly.

## Priority Issues

**[P2] EvaluationTable exposes raw API method codes.**
`frontend/src/components/results/EvaluationTable.tsx:71-75` renders `{m}` (the `MethodName` enum string) literally as `<TableHead>` content. Same component on line 90 renders `{row.bestMethod}` inside a `Badge` with `className="capitalize"`, which does nothing for snake_case (`hermite_divided_difference` becomes `Hermite_divided_difference`, not `Hermite Divided Difference`).
Why it matters: every user who opens the Evaluations tab on a Phase 2 method sees raw API identifiers that read as either a typo or a debug panel. Direct violation of "Match System / Real World".
Fix: hoist the existing `METHOD_LABEL` constant from `GuidedExplanation.tsx:18-30` into `lib/method-labels.ts` and use it in both the column header and the best-method Badge. Drop the `capitalize` utility.
Suggested command: **`/impeccable clarify`** for copy hygiene; **`/impeccable polish`** to land the Badge variant alignment in the same pass.

**[P2] PolynomialCard double-signals piecewise notice and prints raw backend code in the Alert body.**
`frontend/src/components/results/PolynomialCard.tsx:117-122` always renders `<Alert>` with `polynomial.expanded_omitted_reason` as the body. When `isPiecewiseNoGlobal` is true (line 64), the Expanded tab body separately renders a friendly notice on lines 142-145. Result on a cubic-spline run: an Alert reading literally `piecewise_method_no_global_polynomial`, then a body sentence saying the same thing in English.
Why it matters: it is the Phase 2 surface most likely to read as "the tool is broken on cubic splines". It also breaks "Match System / Real World" again, this time inside an Alert component the design system reserves for elevated notices.
Fix: route `expanded_omitted_reason` through `getWarningLabel(code)` from `lib/warnings.ts:55-57`, suppress the Alert entirely when `isPiecewiseNoGlobal` is true, or do both.
Suggested command: **`/impeccable clarify`**.

**[P2] Examples panel approaches the identical-card-grids anti-pattern; the colorize-pass spec it claims to implement no longer matches the code.**
`frontend/src/components/ExamplesPanel.tsx:7-19` ships three categories (`lagrange | function | table`) with badge variants `default | info | secondary`. The most recent prior critique (`2026-05-23T21-30-00Z__frontend-colorize.md`) specified three different categories (`Lecture | Function | Demo`) with `primary | info-cyan | warning-amber` mapping, with the Runge example as Demo specifically so amber pre-flagged the cautionary tale. The shipped code does not match the snapshot. Twelve cards in `xl:grid-cols-4` with identical internal structure (title, subtitle, tinted Badge, source note, outline "Load Example" button) is also the wall the identical-card-grids ban was written to catch.
Why it matters: the largest decision point in the empty bench is now visually flat (most cards are `secondary` table-tinted). First-time users face twelve roughly-equal options with no strong "start here" signal. Returning users cannot pick "the cautionary one" by color any more.
Fix (one of, not both): (a) restore the `Lecture | Function | Demo` taxonomy from the colorize snapshot and reclassify the Phase 2 examples accordingly (Newton Forward / Backward / Stirling become `Lecture`, Hermite / Cubic Spline become `Function` if pinned to an analytic f, the Runge and Osculating-Deferred examples become `Demo`); (b) collapse to four "Quick Start" cards visible by default and put the rest behind a "Show 8 more lecture examples" disclosure, then update or archive the colorize snapshot.
Suggested command: **`/impeccable distill`** (option b) or **`/impeccable colorize`** (option a).

**[P3] GuidedExplanation breaks the three-voice contract.**
`frontend/src/components/results/GuidedExplanation.tsx:135` (`<p className="... font-mono ...">`) and `:152` (`<p key={line} className="font-mono ...">`) use Tailwind's default `font-mono` instead of the project's `.font-numeric` handle. No `tabular-nums`, no fallback stack, defended only by Tailwind's CSS variable.
Why it matters: at 200 percent zoom the polynomial line jitters because the fallback stack does not include JetBrains Mono. The deviation is invisible most of the time and exactly the kind that grows.
Fix: swap `font-mono` for `font-numeric` on both lines.
Suggested command: **`/impeccable polish`**.

**[P3] Em dashes in user-facing copy.**
`lib/warnings.ts:48` (`label: "Piecewise — No Global Polynomial"`) and `ExamplesPanel.tsx:246` (`title: "Deferred — Osculating (Bessel-style)"`). Both render to the user; both were introduced in Phase 2.
Why it matters: copy hygiene rule from the parent skill ("No em dashes. Use commas, colons, semicolons, periods, or parentheses"). Easy to miss; easier to land.
Fix: replace each em dash with a colon (`Piecewise: No Global Polynomial`, `Deferred: Osculating (Bessel-style)`).
Suggested command: **`/impeccable clarify`**.

**Maya, Numerical-Analysis Student** (project-specific persona inferred from PRODUCT.md primary user definition). ## Minor Observations

- ExamplesPanel section title "Lecture Examples" does not match the colorize snapshot's `Demo / Function / Lecture` categorization. The snapshot is now historical; either archive it or bring the code back to register.
- EvaluationTable best-method Badge is hardcoded `secondary`; SummaryCard's methods row is role-tinted via `METHOD_BADGE`. Visual continuity gap on the same screen.
- `App.tsx:206` uses `bg-primary/8`, an opacity step that diverges from the rest of the codebase's /5 /10 /15 /20 ladder.
- `FormState.exact: boolean | null` (`InputPanel.tsx:24`) but `PrecisionSettings`'s Switch only emits `true`/`false`; the `null` third state has no UI.
- `HealthIndicator` `useEffect` deps array is empty (correct only because of the `useRef`) and undocumented.
- PrecisionSettings preset chips use `aria-pressed` (good for AT) but the visual active state is color only at the same lightness as inactive; pair with weight change or check icon.
- `index.css:200-209` reduced-motion block claims to be the "complete set of non-essential motion entry points" but does not neutralize Tailwind's `animate-pulse` used by `Skeleton.tsx` and `HealthIndicator.tsx`.
- "Bessel-style" appears in three example subtitles as jargon for the data set, not the method; Maya may briefly think Bessel functions are involved.
- PolynomialCard Factored tab still renders `CopyableFormula` for missing `factored` values with a "Not available for this degree" fallback. Copy button visible for an unavailable string.
- `GraphCard.tsx`'s `useGraphTokens` `MutationObserver` re-resolves OKLCH strings on every `class`/`data-theme` change; bounded, but watch under heavy theme thrash.

## Questions to Consider

1. Should the Examples panel split into "Quick Start" (3-4 curriculum cards) and "Lecture Catalog" (8-9 behind a disclosure) to keep first-paint cognitive load below the twelve-card wall, or restore the colorize-pass `Lecture / Function / Demo` taxonomy?
2. Is the family taxonomy in MethodSelector pedagogically right, or would "What do you have? / What do you want?" routing serve students better than method genealogy?
3. Should a `lib/method-labels.ts` exist? Three components currently duplicate or omit the code-to-label mapping; centralizing fixes Match-Real-World plus several minor inconsistencies in one pass.
4. Should `PolynomialCard` and `WarningsDisplay` route every backend code through a shared `lib/backend-codes.ts`? `WarningsDisplay`/`ErrorNotice` already do; `PolynomialCard` does not, and its raw `expanded_omitted_reason` rendering is the visible gap.
5. Is the colorize-pass register from `2026-05-23T21-30-00Z__frontend-colorize.md` still binding? Phase 2 shipped a different example taxonomy; either archive the snapshot as historical or bring the code back to register.
6. Should Display digits affect the KaTeX rendering as well as the plain-text fallback? Asymmetry today: at Display 6 the plain text drops to 6 terms while the KaTeX still shows 50-digit coefficients.
